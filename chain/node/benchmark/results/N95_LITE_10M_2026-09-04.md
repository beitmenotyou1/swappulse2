# Intel N95 mini-server — lite-node 10-minute baseline

Date: 2026-09-04

Role: SwapPulse lite node v0.1

Host:

- Intel N95-class mini-server
- 4 CPU cores
- 15.9 GB RAM reported by Node.js
- Ubuntu Linux kernel 7.0.0-30-generic
- root filesystem 466 GB, 25% used before test
- host swap configured at 4 GB and already almost fully allocated before the test

## Result

Short-run qualification: **PASS**

This is a first reference measurement only. It is not yet a production hardware support claim because restart, catch-up, low-disk, unclean shutdown and multi-day soak tests remain outstanding.

Observed over 600 seconds / 120 samples:

- availability: 100%
- failed samples: 0
- host CPU busy average: 20.98%
- host CPU busy maximum: 49.5%
- minimum host available memory: 4,339,687,424 bytes (~4.04 GiB)
- minimum swap free: 167,936 bytes
- status/RPC latency average: 9.58 ms
- status/RPC latency maximum: 102 ms
- final lite-node readiness: true
- final trust mode: `single-peer-degraded`
- final independent verification: false
- healthy peers: 1
- frozen V2 pins: remained verified
- common height during final probe: 51

Container snapshots around the run showed approximately 29–49 MiB of memory usage and effectively idle CPU at the instant of each `docker stats --no-stream` sample.

The initial benchmark's CPU figure is host-wide and must not be interpreted as lite-node CPU consumption. Benchmark schema v2 adds direct Docker container CPU/RAM/network/block-I/O measurements plus Linux PSI pressure metrics.

## Swap interpretation

The first line of each `vmstat` sample set showed non-zero `si`/`so`, which is the cumulative/average line since boot. The subsequent one-second interval rows showed `si=0` and `so=0` throughout the observed samples.

Conclusion: the host's swap allocation was full but cold during this test. There was no evidence of sustained active swap thrashing attributable to the lite node. Do not run `swapoff` merely to make the swap-used number look cleaner.

## Trust interpretation

The lite node correctly remained:

```text
trust_mode = single-peer-degraded
peer_agreement = false
independently_verified = false
```

Only one genuine SwapPulse RPC/full execution source exists today. The node verified the expected chain ID and frozen V2 contract class hashes and blocked write methods, but it correctly did not convert single-source agreement into an independence claim.
