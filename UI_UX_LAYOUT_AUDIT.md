# SwapPulse UI/UX and Overall Layout Audit

**Audit date:** 11 September 2026  
**Scope:** Overall information architecture, application shell, navigation, page hierarchy, responsiveness, breakpoint interactions, sticky/fixed UI, mobile/PWA ergonomics, accessibility of visible controls, interaction feedback, loading/error/empty states, settings/profile organisation, task-workspace layouts, consistency and design-system use. Backend, blockchain and AT Protocol internals are excluded except where they directly create a visible UX failure.  
**Validation:** `npm run build` passes. `npm run lint` passes. `npm run typecheck` fails with widespread component/prop contract errors.  
**Status:** **NOT UI/UX RELEASE READY**. Several P0 interaction and breakpoint failures remain.

| Priority | Area | Finding | Required action |
| --- | --- | --- | --- |
| 🔴 P0 | Mobile primary actions | Authenticated mobile layouts mount the Compose FAB and global Share FAB at exactly `fixed bottom-20 right-4 z-40`. Share is mounted after MobileNav, so the two primary actions occupy the same position and one can obscure/intercept the other. | Replace independent FAB positioning with one shared mobile action stack that reserves safe-area space. Give Compose, Share and any other floating actions distinct positions and regression-test 320, 360, 375, 390 and 430 px widths plus installed-PWA mode. |
| 🔴 P0 | Messages responsive layout | The global shell adds a 320 px RightSidebar at `lg` while Messages simultaneously expands its conversation list to `lg:w-96` (384 px). At a 1024 px viewport the shell leaves roughly 632 px for the main column, so the actual message thread can collapse to about 248 px. The layout becomes narrower at 1024 px than at 768-1023 px. | Make Messages a route-specific workspace layout that suppresses the social RightSidebar and gives the thread priority. Define breakpoint tests around 768, 1024, 1280 and 1400 px and set a minimum usable thread width. |
| 🔴 P0 | Podcast player / mobile nav | `StickyPlayerBar` uses `bottom-16` below 640 px but switches to `sm:bottom-0` at 640 px, while MobileNav remains fixed until `md` (768 px). Between 640 and 767 px the player can sit underneath/behind the mobile bottom navigation. | Use the same shared bottom-navigation inset token for the player at every mobile breakpoint. Do not switch the player to `bottom-0` until MobileNav is actually removed. |
| 🔴 P0 | Set navigation | `/set/:setId` renders `Explore`, and recent-set cards link to that route, but Explore never reads `setId` from route params. Clicking a set can therefore reopen generic Explore instead of the selected set. | Read `setId` with `useParams`, initialise/synchronise the set filter from the route and preserve it through back/forward navigation. Add direct-entry and recent-set-card tests. |
| 🔴 P0 | Collector search | The main Search page calls `search-profiles` with `{ query, limit }`, while the backend currently accepts only `{ field, value, limit }`. The failure is swallowed into an empty result set, so a broken collector search looks like “no collectors found”. | Create one supported free-text collector-search contract, use it consistently, and show per-source failure/retry state instead of false zero-result UX. |
| 🔴 P0 | Feedback interaction/privacy | Opening the global Feedback control immediately screenshots `document.body` and uploads the image before the user explicitly chooses to attach it or submits feedback. The control is available on Messages, Wallet, Settings, Admin and other sensitive pages. Cancelling leaves the already-uploaded image behind. | Make screenshot attachment explicitly opt-in. Capture locally for preview, redact/exclude sensitive areas, upload only after confirmation/submission and clean up abandoned uploads. Never surprise-capture a private workspace. |
| 🟠 P1 | Global fixed-layer system | Floating UI is positioned independently: Compose and Share use `bottom-20`, Feedback uses `bottom-36`, notification banners use `bottom-20` with z-index 100, cookie consent sits at `bottom-0` z-index 50, and the podcast player has its own bottom offsets. Notification banners can directly cover Compose/Share. | Introduce shared layout variables/components for bottom-nav height, safe area, player height, FAB stack and transient banners. Compute one collision-free action zone rather than hard-coding offsets in each feature. |
| 🟠 P1 | Universal app shell | The same feed-oriented shell, including the 320 px RightSidebar, is used for social feeds and task workspaces such as Messages, Settings, Wallet, Admin and Moderation. This spends valuable width on recommendations/portfolio/trending while dense work UIs are compressed. | Add route/layout families: social-feed shell, focused workspace shell, full-width administrative shell and standalone detail shell. Keep the common brand/navigation system but vary secondary columns by task. |
| 🟠 P1 | Desktop breakpoint balance | At `lg` the RightSidebar appears while the LeftNav is still the narrow 72 px icon rail until `xl`. The main content can drop to about 632 px at 1024 px, creating a visually abrupt and sometimes harmful layout transition. | Move the RightSidebar to a wider breakpoint, make it responsive/collapsible, or enable it only on routes that benefit from it. Test effective main-column width rather than viewport width alone. |
| 🟠 P1 | Mobile bottom navigation | Authenticated users get five primary destinations plus More plus the Theme toggle, creating seven equal slots across a phone. Labels are only 10 px and the theme slot has no visible text label, making the navigation crowded and harder to scan. | Keep 4-5 true primary destinations. Move Theme into More/settings, preserve large touch targets and use a clearly prioritised mobile information architecture. |
| 🟠 P1 | Route/tab state preservation | App-wide `AnimatePresence` keys the whole route tree by `location.pathname`, so switching routes unmounts and remounts page components. MobileNav saves pathname and scroll position, but not local filters, loaded data, drafts or tab state, despite presenting the interaction as native-style tab preservation. | Preserve primary-tab page state with nested routes/cache/state stores or avoid remounting the entire route tree. Define which state survives tab switching and test it explicitly. |
| 🟠 P1 | PageHeader navigation | `PageHeader` hides Back only on `/`, `/explore`, `/trades` and `/collection`. `/wallet` is a primary mobile tab but still shows a Back button. Direct-loaded pages use `navigate(-1)`, which can be meaningless or leave the expected product context. | Define root destinations centrally and use context-aware fallback routes. Primary tab roots should never behave like subordinate detail pages. |
| 🟠 P1 | PageHeader action space | `PageHeader` places title/subtitle and arbitrary children in one unwrapped `justify-between` row with no mobile action-overflow strategy. Pages such as Trade Board place two full text actions in this area, which can squeeze/truncate headings or actions on narrow screens and in longer translations. | Add a responsive PageHeader API with primary action, overflow menu and mobile stacking/compact behaviour. Test translated text at narrow widths. |
| 🟠 P1 | Sticky header offsets | Challenges uses `sticky top-[57px]` for its filter block even though PageHeader height varies with subtitle, safe-area inset and font/content. Other sticky content such as Explore's selection bar uses `top-0`. These hard-coded independent sticky layers can hide under the header or create gaps. | Publish a shared header-height/sticky-offset CSS variable or layout context and use it for all secondary sticky bars. Avoid magic pixel offsets. |
| 🟠 P1 | Home information hierarchy | On signed-in Home, the actual followed feed is preceded by category controls, rarity controls, Stories, Spaces, optional pack content, Card of the Day, Trending Cards, Compose and Trade Interest. The core “people I follow” content can be pushed several screens below auxiliary modules. | Choose one clear Home job. Keep Compose plus 1-2 compact discovery modules above the feed and move the rest to Explore or collapsible rails. Measure first-feed-card visibility on common phones. |
| 🟠 P1 | Guest Home hierarchy | Guests render an empty sticky feed-tab container because `TABS=[]`, but still get RarityFilter, Stories, Spaces, Card of the Day, Trending, ComposeBox and Trade Interest before the welcome/registration state. The first-visit journey is visually noisy and includes controls that imply signed-in capabilities. | Give guests a deliberate landing/feed variant: concise value proposition, Explore/search preview and clear sign-in/create-account actions. Do not render irrelevant feed controls or composer affordances. |
| 🟠 P1 | Settings information architecture | Settings exposes 13 sections as one horizontally scrolling tab row. On mobile and the narrow desktop centre column, most categories are off-screen with no category index or clear overflow cue. Important areas such as Security, Data Rights and AT Protocol can be difficult to discover. | Use grouped Settings navigation: Account, Privacy & Safety, Notifications, Accessibility, Connections and Advanced. On mobile use a section list or select/sheet; on desktop use a vertical settings sidebar. Preserve deep links. |
| 🟠 P1 | Collection information architecture | Collection exposes seven horizontally scrolling top-level tabs, an always-visible three-card stats strip, rarity chips, sort and selection controls. The card-management view becomes control-heavy before users reach their collection. | Group secondary tools such as Import/Export and Insurance under More/Tools, keep core tabs visible, and make stats collapsible or context-specific on small screens. |
| 🟠 P1 | Explore sticky selection bar | The selected-cards toolbar is `sticky top-0 z-20`, while PageHeader is `sticky top-0 z-30`. The selection toolbar can slide underneath the PageHeader instead of stacking below it, reducing visibility of bulk actions. | Use the shared sticky offset below PageHeader and keep bulk actions fully visible. |
| 🟠 P1 | Card detail navigation | CardDetail hard-codes its Back link to `/explore`. A card opened from Collection, Search, Set checklist, Trades or another profile therefore loses the user's original context. | Prefer history-aware Back with a safe route fallback, or pass an explicit `from` context. Preserve filters/scroll when returning to the source surface. |
| 🟠 P1 | Card detail page length | CardDetail stacks overview data, actions, market price, price history, variant pricing, three separate market-provider panels, variants, weakness/resistance, legality, Pokémon profile, evolution, set rail, reviews and social content into one very long page. There is no local section navigation. | Consolidate duplicated market information and introduce grouped accordions/section tabs or a sticky contents selector. Prioritise card identity, collection/trade actions and one price summary first. |
| 🟠 P1 | Trade card responsiveness | TradeBoard listing footers use a non-wrapping `justify-between` row. Multiple shipping-region chips occupy the left side while owner/negotiate buttons occupy the right, so narrow phones or long region labels can squeeze or push actions out of the comfortable viewport. | Let metadata wrap independently and move actions to a full-width secondary row on small screens. |
| 🟠 P1 | Search failure state | Card, collector and federated searches independently convert errors into empty arrays. The combined UI then shows “No results”, so users cannot distinguish service outage, partial federation failure and a genuine empty search. | Track source-level status and render partial-results/error chips with retry actions. Never turn transport/server errors into semantic “zero matches”. |
| 🟠 P1 | Signed-out action affordances | Public browsing surfaces several write-oriented controls before authentication, including the Home composer and card/wishlist-style actions. Users discover the sign-in requirement only after trying the action or receiving an error. | Use an auth-aware action component that changes CTAs to “Sign in to …”, keeps the intended return route and explains which capabilities are available to guests. |
| 🟠 P1 | Sharing on private workspaces | Layout mounts the global Share FAB on Messages, Settings, Wallet, Admin and Moderation as well as public content. Sharing the current path is often meaningless or undesirable on those routes. | Make sharing route/resource-aware. Hide it on private/internal workspaces and expose share controls only where a stable public resource has useful metadata. |
| 🟠 P1 | Modal accessibility/consistency | Source inspection finds 43 custom `fixed inset-0` overlays but only 7 explicit `role="dialog"` occurrences. Many bespoke overlays therefore bypass the shared Radix Dialog/Sheet behaviour for focus trapping, Escape handling, labelling and focus restoration. | Migrate modal families to shared Dialog/AlertDialog/Sheet/Drawer primitives. Add keyboard-only and screen-reader regression tests. |
| 🟠 P1 | Settings switch labelling | Shared `SettingRow` renders visible label/description text beside a Radix Switch without `id`, `aria-labelledby` or `aria-describedby`, so the control itself lacks a reliable programmatic name. | Make SettingRow generate and bind stable label/description IDs to every switch. Keep the whole row clickable where appropriate while preserving focus semantics. |
| 🟠 P1 | Tablet legal/help navigation | Between `md` and `<lg`, MobileNav is hidden and RightSidebar is not yet present. LeftNav's More dialog contains feature/account/admin groups but no Docs, Status, Terms, Privacy, Chain, Donate or GitHub links, creating a discoverability gap unique to tablet widths. | Add essential help/legal links to desktop More or provide a compact global footer independent of RightSidebar. |
| 🟠 P1 | Cookie banner small-screen layout | The cookie banner is fixed to the viewport bottom and expanded preferences can add four category rows plus actions, but the banner itself has no maximum height or internal vertical scroll. On short phones/landscape it can cover most of the application or make lower actions difficult to reach. | Add `max-height` based on `dvh`, internal scrolling and safe-area padding. Treat it as a proper consent sheet on mobile and test landscape/small-height devices. |
| 🟠 P1 | Touch target consistency | PageHeader Back is roughly a 32 px control (`20px` icon + `p-1.5`), and several custom close/icon buttons use similarly small padding, while newer profile navigation deliberately uses 44 px targets. Touch accessibility is inconsistent across the app. | Standardise interactive icon buttons to at least a 44x44 px hit area without visually bloating the icon. Enforce this through a shared IconButton component. |
| 🟡 P2 | RightSidebar behaviour | RightSidebar is not route-aware or viewport-sticky. Its portfolio/trades/online/trending/recommendations stack can grow long, while the footer's `mt-auto` does not guarantee a viewport-bottom footer because the aside itself is not given a viewport-height layout. | Make the sidebar sticky/scroll-aware on social routes or simplify it to a shorter contextual panel. Do not rely on `mt-auto` without an explicit height/flex context. |
| 🟡 P2 | Global text selection | `body { user-select: none }` disables normal selection across most interface text, re-enabling it only for selected content classes. This makes handles, card names, prices, IDs and general UI copy unnecessarily difficult to copy. | Default to selectable text. Disable selection only on drag handles, tabs and controls where selection genuinely harms interaction. |
| 🟡 P2 | Reduced motion | SwapPulse has an in-app `.reduce-motion` class but does not automatically honour the operating system's `prefers-reduced-motion` preference. Route transitions and pulse animations therefore run for users who have already requested reduced motion at OS level. | Initialise motion preference from `prefers-reduced-motion` and allow an explicit in-app override. Apply it before the first animated paint. |
| 🟡 P2 | Native browser dialogs | Source scan finds 58 `alert()`/`confirm()` calls. These interrupt flow, look inconsistent with the visual system, have uneven mobile behaviour and bypass the shared accessible dialog/toast patterns. | Replace them with AlertDialog/Dialog/toast patterns based on severity and reversibility. |
| 🟡 P2 | Auth-page navigation | Standalone authentication pages do not inherit the main shell and lack a strong home/public-browsing escape plus compact Help/Terms/Privacy navigation. This weakens orientation and trust during sign-in/recovery. | Add a clear SwapPulse logo/home link and a compact legal/help footer without introducing the full social shell. |
| 🟡 P2 | Search card imagery | Search result cards render portrait trading-card art into `h-32 w-full object-cover`, which crops the very card artwork users are searching for. | Use the shared CardImage/aspect-ratio treatment with `object-contain` and a neutral background. |
| 🟡 P2 | Search localisation | The Search page still contains hard-coded English headings, placeholder text and empty states while the surrounding application is localised. | Move all Search copy into the i18n catalogue and test long translations against the result-card/header layouts. |
| 🟡 P2 | Contextual documentation | `DocumentationLink` accepts a `slug` and writes it to a data attribute, but every link still opens the documentation root. The visible “official documentation” affordance therefore loses page context. | Maintain a real slug-to-GitBook route map and deep-link each contextual help affordance to the relevant page. |
| 🟡 P2 | Status/loading hierarchy | Several user-facing fetches still convert failures to empty states or silent fallbacks. On Home, a failed feed load becomes the same “quiet” experience as legitimately having no followed posts. | Give core surfaces explicit loading, empty, partial and error states with source-specific retry. Use skeletons where layout stability matters. |
| 🟡 P2 | Top-banner stack | Alpha plus Sign-in or Activation banners can stack above each page before a sticky PageHeader. On small displays this consumes a large portion of the first viewport and shifts the core task downward. | Collapse global notices into one dismissible status strip or prioritised banner stack. Do not show multiple low-priority notices simultaneously on compact screens. |
| 🟡 P2 | Frontend type contract | The exact `/app` checkout builds and lints successfully, but `npm run typecheck` fails with a large set of prop/component-contract errors across shared UI primitives, Settings, profile themes, feeds, authentication and other visible surfaces. | Treat typecheck as a release gate and repair shared primitive typings/required-prop drift first. Add component-level tests for the high-traffic surfaces touched by those errors. |
| 🟢 P3 | Theme toggle navigation semantics | In the mobile bottom nav, ThemeToggle visually occupies the same navigation row as destinations but is an unlabeled state-changing utility rather than a destination. | Move Theme to More/Settings or give utilities a clearly separate treatment from primary navigation. |
| 🟢 P3 | Visual consistency debt | The core token system is consistent, but feature growth has produced multiple parallel tab styles, card radii, custom modals, custom headers and magic spacing offsets. The app increasingly relies on per-feature Tailwind strings instead of a small set of layout primitives. | Consolidate around shared PageShell, PageHeader, SectionTabs, StickySubnav, EmptyState, ErrorState, WorkspaceShell, MobileActionStack and responsive modal primitives. |

## Verified UI/UX strengths

The audit also confirmed foundations worth preserving. SwapPulse has a coherent light/dark token system, consistent primary/accent/success/warning/destructive colours, route-level lazy loading, a main skip-to-content link, global focus-visible styling, safe-area handling in MobileNav and PageHeader, a grouped and keyboard-aware profile tab component, good use of Radix primitives in newer areas, responsive card/set grids, contextual loading states on many pages, a clear max-width shell, and a generally consistent rounded-card visual language. The profile tab navigation is notably stronger than several older tab systems because it intentionally moves overflow sections into a keyboard-operable More menu.

## Recommended remediation order

1. Fix the exact mobile FAB collision and introduce a shared bottom-action/inset system.
2. Create route-specific workspace shells, beginning with Messages, then Settings, Wallet, Admin and Moderation.
3. Fix the 640-767 px podcast-player overlap and all secondary sticky-offset collisions.
4. Repair set navigation and collector search so navigation/search promises match user outcomes.
5. Redesign mobile primary navigation and Settings/Collection information architecture.
6. Simplify Home hierarchy and signed-out states.
7. Make headers/actions/contextual Back behaviour responsive and predictable.
8. Migrate custom overlays and small icon controls to accessible shared primitives.
9. Replace false empty states with explicit error/partial states and replace native dialogs.
10. Bring typecheck back to green, then run visual regression/accessibility checks at phone, tablet and desktop widths.

## Release decision

SwapPulse should not be considered UI/UX release-ready until the unresolved P0 findings are fixed and the key responsive paths are re-tested at representative viewport widths. Build and lint passing are positive, but they do not compensate for the exact mobile collisions, workspace breakpoint collapse, broken set/search journeys or failed typecheck gate.
