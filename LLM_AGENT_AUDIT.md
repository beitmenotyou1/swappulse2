# SwapPulse LLM / Agent Audit

**Audit date:** 11 September 2026  
**Scope:** Base44 agents, LLM-backed backend functions, moderation automation, agent feedback/learning, RAG/project knowledge, image analysis, AI-generated trends, agent UI data exposure and autonomous workflows.  
**Status:** High-impact remediation complete; residual verification/documentation actions remain.

| Priority | Area | Finding | Required action |
| --- | --- | --- | --- |
| 🔴 P0 | Card verification | `CardVerificationSession` verification level/status could be influenced from the user side while minting trusted the resulting session. | **Completed:** verification sessions are service-managed for create/update and the trusted verification result is backend-issued. |
| 🔴 P0 | Possession badge | Level 0 self-attestation and Level 1 partial matches were being treated too much like verified physical possession. | **Completed:** the possession-verified trade badge now requires Level 2 or higher. |
| 🔴 P0 | Card vision trust boundary | Card attestation accepted caller-supplied card identity and arbitrary HTTPS scan URLs, allowing the caller to shape the verification target and media source. | **Completed:** derive card identity from the authenticated collector's `CollectionEntry`, use private uploads, prove file access and create short-lived signed URLs only for model analysis. |
| 🔴 P0 | AI moderation authority | Automated moderation retained capability to hide content, issue labels, increment strikes, restrict accounts and notify users based on an LLM result. | **Completed:** `ai-moderation` is advisory-only and dormant enforcement code for those model-driven actions was removed. |
| 🔴 P0 | Toxic-label enforcement | Toxic-label handling could escalate model output into strikes or account restrictions. | **Completed:** automatic toxic-label enforcement is on security hold; the handler is advisory and durable account punishment requires an explicit human moderation decision. |
| 🔴 P0 | Agent excessive agency | Specialist agents could previously mutate listings or publish community content. | **Completed:** Trade Assistant, Sentiment Assistant and Moderation Agent are read-only; recommendations/drafts must be applied through normal user/staff controls. |
| 🔴 P0 | Moderation learning poisoning | A signed-in user could submit fairness feedback against moderation decision IDs without proving they were an affected party, and repeated submissions could distort learning. | **Completed:** bind fairness feedback to the affected authenticated account, resolved cases only, one rating per account, replay protection and stable sum/count aggregation. |
| 🟠 P1 | Multimodal prompt injection | Card photos can contain hostile text, QR codes, URLs or instructions that attempt to redirect the vision model. | **Completed:** image content is explicitly untrusted; the model must ignore embedded instructions/URLs and perform only the narrow visual possession check. |
| 🟠 P1 | Authenticity overclaim | Vision output risked being interpreted as a card authenticity or professional grading determination. | **Completed:** prompts, schema and UI language now frame the result as a visual possession check, not proof of authenticity or professional grading. |
| 🟠 P1 | Vision decision threshold | A weak or screen-based match could reach a meaningful verification level. | **Completed:** Level 2 now requires a matching expected card, confidence at least 0.85, visible physical card, no screen/digital reproduction and no suspected image manipulation. |
| 🟠 P1 | Agent feedback provenance | Collectors could create learning records with workflow-only fields such as accepted/rejected suggestions or processed state. | **Completed:** collector feedback goes through `submit-agent-feedback`, which is authenticated, rate-limited and restricts user-submitted types to thumbs up/down/correction. |
| 🟠 P1 | Learning namespace injection | `processAgentFeedback` accepted a caller-supplied agent name and could create an unintended learning namespace. | **Completed:** processing is restricted to the fixed recognised-agent allowlist. |
| 🟠 P1 | Learning bookkeeping | Processing at most 100 feedback rows could still mark every matching unprocessed row as processed. | **Completed:** only the exact feedback records actually analysed are marked processed. |
| 🟠 P1 | RAG approval bypass | Safety-flagged learning insights or knowledge snapshots could previously be approved after an administrator acknowledgement. | **Completed:** flagged material now fails closed and cannot be approved. It must be rejected and replaced by a clean curated version. |
| 🟠 P1 | RAG admin UI | The admin interface still offered an “approve” path for safety-flagged knowledge/insights after the backend was changed to fail closed. | **Completed:** approval controls are disabled for flagged candidates and the UI explains that a clean replacement is required. |
| 🟠 P1 | RAG poisoning | Project documentation changes could influence Helper without strong source provenance or quarantine. | **Completed:** knowledge refresh uses a fixed source allowlist, immutable Git revision, SHA-256 hash, safety screening, admin-only quarantine and explicit publication review. |
| 🟠 P1 | Moderation memory/privacy | Persistent moderation-agent memory risked sensitive case information bleeding between review conversations. | **Completed:** persistent moderation-agent memory is disabled and other-conversation context is not included. |
| 🟠 P1 | Raw tool-data exposure | Specialist-agent UIs exposed raw tool arguments/results, potentially revealing internal record structure, IDs or private contextual data. | **Completed:** raw payloads were removed while useful tool success/failure state remains visible. |
| 🟠 P1 | Collection-opportunity integrity | `analyzeCollectionOpportunity` trusted browser-supplied card name, set and market/purchase values despite authenticating the caller. | **Completed:** the endpoint now accepts an owned `CollectionEntry` ID and derives authoritative card/pricing context server-side. |
| 🟠 P1 | Web trend prompt injection | Internet-context trend generation could ingest hostile instructions from pages/snippets and return unsanitised model text. | **Completed:** internet material is explicitly untrusted, prompt-injection instructions are rejected, output fields are normalised/length-limited and the six-hour retry/cost cache remains in place. |
| 🟠 P1 | Model bias / unnecessary profile data | Moderation classification was given existing strike count, restriction state and prior flagged-post count. | **Completed:** classification is now based on the content itself; staff can review account history separately when deciding enforcement. |
| 🟠 P1 | Autonomous scheduler identity | AI moderation, learning, knowledge refresh, trade-opportunity and sentiment workflows can be invoked by schedules whose privileged internal identity is not currently platform-verifiable. | **Completed for safety:** affected autonomous AI workflows are on explicit security hold instead of weakening function authentication. Re-enable only when Base44 supplies a verifiable internal scheduler identity. |
| 🟠 P1 | Agent authentication default | Some agents relied on the platform default rather than explicitly prohibiting anonymous access. | **Completed:** all eight agents now set `allow_anonymous_access: false`. |
| 🟡 P2 | Specialist prompt-injection wording | Not every specialist prompt originally stated as clearly as Helper that retrieved listings/messages/records are untrusted data. | **Partially completed:** Trade Assistant now includes the explicit indirect prompt-injection/privacy rule. Add the same wording to the remaining specialist prompts for defence in depth. |
| 🟡 P2 | AI documentation drift | Some older assistant documentation describes broader automation/data use than the hardened read-only architecture now permits. | Synchronise the GitBook-synced assistant documentation using the required GitBook editing workflow and state the read-only/human-confirmation boundary consistently. |
| 🟡 P2 | Post-change build verification | Base44 MCP file operations worked, but the command sandbox mounted an empty `/workspace`, preventing final `npm run build`, `npm run lint` and `npm run typecheck` execution after the agent changes. | Re-run build, lint and typecheck as soon as the repository is correctly mounted; do not treat the release gate as green until those checks pass. |
| 🟢 P3 | Audit consistency | LLM/Agent findings were originally recorded across chat summaries instead of a standard project audit table. | **Completed:** this audit is now recorded in the shared four-column SwapPulse audit format. |

Future AI/agent audits must use [AUDIT_STANDARD.md](AUDIT_STANDARD.md).
