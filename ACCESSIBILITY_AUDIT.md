# SwapPulse Accessibility Full Feature Audit
**Audit date:** 13 September 2026  
**Scope:** Whole-product accessibility: keyboard, focus, screen readers/ARIA, colour and non-text contrast, media alternatives, motion/timing, zoom/reflow, target size, forms/status, dialogs, feeds, Stories, Voice Spaces, podcasts, charts, authentication, Settings, Admin/Moderation, localisation, generated PDFs and accessibility governance.  
**Overall score:** **14/100**  
**Risk:** **Critical / High Risk**  
**Release status:** **NOT RELEASE READY for a WCAG 2.2 AA accessibility claim**  
**Findings:** **71 total - 7 P0, 40 P1, 23 P2, 1 P3**  
**Verification status:** Source/design-system/standards audit complete. Exact-release build/lint/typecheck, browser automation, screen-reader testing, 400% zoom and physical-device testing were unavailable in the Base44 command environment.
> The project-required Base44 web-agent README could not be read from the sandbox because the endpoint returned HTTP 403. Root README.md, AUDIT_STANDARD.md and AGENTS.md were inspected. No functional application code or user data was changed by this audit.

## Findings
| Priority | Area | Finding | Required action |
|---|---|---|---|
| P0 | **AC-001 - Colour contrast** | Light-theme semantic text tokens fail WCAG AA in normal-size use: success #10b981 on white is about 2.54:1, warning #f59e0b about 2.15:1 and destructive #ef4444 about 3.76:1. These tokens are used extensively for errors, warnings, moderation, status and security text. | Replace semantic foreground tokens with AA-safe colours for every supported background/state and regression-test the token matrix at 4.5:1 for normal text and 3:1 only for qualifying large text. |
| P0 | **AC-002 - Non-text contrast** | Core light-theme borders and control boundaries are too faint for WCAG 1.4.11: --border #e2e8f0 is about 1.23:1 against white and --input/--border-strong #cbd5e1 about 1.48:1. Many inputs, cards, checkboxes and segmented controls rely on these boundaries. | Raise component-boundary and state contrast to at least 3:1 where the boundary is required to identify the control/state; test light, dark and high-contrast modes. |
| P0 | **AC-003 - Prerecorded video** | NativeVideoPlayer and Story video have no caption track or caption/transcript model. ## Executive assessment
SwapPulse has a better accessibility foundation than several of its individual feature implementations suggest. The app already has a skip link, a visible global focus indicator, a meaningful main landmark, good shared Radix primitives, good form ARIA helpers, document-language switching, alt-text authoring, and an unusually solid Profile tab implementation. Those foundations should be preserved and reused.

The problem is consistency. Product areas that use the shared primitives are often reasonable; bespoke overlays, custom media controls, visualisations and gesture-heavy experiences frequently bypass those foundations. The result is confirmed WCAG-level failures in contrast, time-based media, keyboard operation and programmatic status/state exposure. The current Help statement that SwapPulse follows WCAG 2.1 AA is therefore not supportable from the inspected implementation.

The strongest release blockers are systemic light-theme contrast, missing captions/transcripts for time-based media, pointer-dependent Story timing, an inaccessible podcast scrubber, and incomplete modal focus handling. These should be fixed before polishing lower-risk labels or spacing because they prevent whole classes of users from perceiving or operating core features.

## Verified strengths to preserve
- Global skip link targets #main-content and the main landmark is present in the shared Layout.
- A global :focus-visible outline is defined rather than removing keyboard focus indication.
- Shared Radix Dialog, Sheet, AlertDialog, Tabs, Select, Checkbox, RadioGroup and related primitives provide a strong accessible foundation when features actually use them.
- ProfileTabNav is a strong implementation: tablist/tab roles, aria-selected, roving tabindex and arrow-key navigation are present.
- Shared form primitives associate descriptions/errors through aria-describedby and expose aria-invalid.
- I18nProvider updates the document <html lang> value to the active locale.
- Compose supports author-supplied image descriptions/alt text and the video composer exposes an alt-text field.
- ExternalLinkConfirm uses the accessible AlertDialog primitive.
- BotChallengeModal uses the shared Dialog primitive and provides a simple non-cognitive fallback rather than forcing a visual puzzle.
- Chain Explorer includes useful live-region/aria-busy/error patterns and is one of the stronger complex-data surfaces.
- Some high-impact security/Web3 operations already use role=status/aria-live for progress and role=alert for failures.
- External embedded video is not loaded until explicit user action and the iframe has a title.

## Important standards evidence
- WCAG 2.2 is the current W3C Recommendation and adds, among other criteria, Focus Not Obscured (AA), Dragging Movements (AA), Target Size Minimum (AA) and Accessible Authentication Minimum (AA).
- WCAG 1.4.3 requires at least 4.5:1 contrast for normal text and 3:1 for qualifying large text.
- WCAG 1.4.11 requires at least 3:1 for meaningful UI component boundaries/states and graphical objects.
- W3C WAI guidance states prerecorded audio-only content such as podcasts requires a transcript/equivalent text alternative at Level A.
- The WAI-ARIA modal dialog pattern expects focus to move inside the dialog, remain contained with Tab/Shift+Tab, support Escape, and return meaningfully when the dialog closes.
- WCAG 2.2 Recommendation: https://www.w3.org/TR/WCAG22/
- Understanding 1.4.3 Contrast (Minimum): https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum
- Understanding 1.4.11 Non-text Contrast: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast
- WAI transcripts guidance: https://www.w3.org/WAI/media/av/transcripts/
- WAI-ARIA APG Dialog (Modal) Pattern: https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
- What's New in WCAG 2.2: https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/

## Required release tests
- Run axe-core/Playwright against every public route, every authenticated route, every Settings/Admin/Moderation section and every modal state; release gate serious/critical regressions.
- Keyboard-only test from fresh page load through all primary tasks: sign in, post, scan, collection, trade, messages, profile, settings, spaces, podcasts, admin/moderation.
- Verify every modal traps focus, has an accessible name, closes with Escape unless destructive workflow intentionally blocks it, and restores focus to the invoking control.
- Test route changes with NVDA+Firefox/Chrome, VoiceOver+Safari/iOS and TalkBack+Android to confirm page-title/main-heading announcement and sensible focus.
- Test light/dark/high-contrast token pairs with automated contrast checks for text, icons, focus indicators and component boundaries.
- Test OS prefers-reduced-motion before sign-in and after sign-in; verify route transitions, live pulses, story progression and decorative animations honour it.
- Test 200% text resize and 400% zoom/320 CSS px reflow in portrait and landscape without lost content/functionality or horizontal clipping.
- Test WCAG 2.4.11 focus-not-obscured with MobileNav, cookie banner, podcast player, share/feedback FABs and virtual keyboard visible.
- Measure every interactive target against WCAG 2.5.8, including shared Switch/Checkbox/Radio/Slider and compact icon controls.
- Verify Story controls have persistent Pause/Resume, Previous/Next, captions/alt text, keyboard support and no pointer-only gesture requirement.
- Verify uploaded videos cannot publish speech content without captions or an equivalent accessible path; test caption toggle with keyboard and screen reader.
- Verify each podcast episode has an equivalent transcript and that the transcript remains available independently of the custom audio player.
- Verify podcast seek/speed/volume/play controls with keyboard, screen reader, switch control and touch.
- Verify all charts have a programmatic summary plus data table/list and that filter state is announced.
- Verify drag/reorder features have Move up/down or position alternatives with focus retained and position changes announced.
- Verify async errors/statuses in authentication, uploads, saves, deletions and admin actions are announced once with correct urgency.
- Verify notification/toast main actions are keyboard reachable and persistent information remains available after auto-dismiss.
- Verify all nine locales, including hard-coded/fallback strings, have correct language pronunciation and no clipped critical controls.
- Generate every downloadable PDF and run PDF accessibility/tagging/reading-order/contrast checks; provide accessible HTML/CSV alternatives where tagging is not viable.
- Run exact release build, lint and typecheck plus accessibility E2E suite from the canonical checkout before claiming WCAG conformance.

## Recommended remediation order
1. Replace light-theme semantic text/border/control tokens with WCAG 2.2 AA-safe values and run a token-level contrast gate.
2. Implement accessible media policy: captions for uploaded video and transcripts for every podcast/prerecorded audio episode.
3. Rebuild StoryViewer accessibility: real modal semantics, explicit pause/resume/navigation, alt text/captions, responsive reflow and reduced-motion behaviour.
4. Replace the podcast scrubber with an accessible slider and add explicit speed/volume controls.
5. Migrate all custom overlays to shared Radix Dialog/Sheet primitives and standardise focus return.
6. Honour OS reduced-motion/colour-scheme preferences before authentication and replace filter-based high contrast with semantic tokens.
7. Fix the Accessibility Settings themselves: labelled switches, radio/pressed states, localisation and accessible Settings navigation.
8. Add SPA route-focus/page-announcement handling and aria-current to navigation.
9. Create one accessible status/loading/toast pattern and migrate authentication plus high-value workflows.
10. Add text/table equivalents for charts and history visualisations.
11. Add non-drag alternatives for profile/binder reordering and increase shared target hit areas.

## Release decision
**SwapPulse should not claim WCAG 2.1 AA or WCAG 2.2 AA conformance in its current state.** The architecture contains reusable accessible primitives, so this is fixable without redesigning the whole product. The immediate release plan should first correct design tokens/media alternatives/Stories/podcast keyboard access, then standardise dialogs/statuses/navigation and finally complete responsive, localisation, document and regression testing.
