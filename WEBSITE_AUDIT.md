# SwapPulse Website Audit

**Audit date:** 11 September 2026  
**Scope:** Website/frontend only: React routes and pages, navigation, responsive behaviour, public/private page UX, search and discovery, forms and actions, settings, privacy controls presented in the UI, accessibility, SEO presentation, PWA/browser behaviour, loading/error states, legal/help discoverability and frontend release verification. Cairo contracts, relay/RPC internals, staking/bridge logic and backend-only architecture are excluded except where they cause a directly visible website failure.  
**Status:** **NOT WEBSITE-RELEASE READY**. Several user-facing release blockers remain.

| Priority | Area | Finding | Required action |
| --- | --- | --- | --- |
| 🔴 P0 | Mobile navigation / Compose | On authenticated mobile layouts, the Compose FAB and global Share FAB both use `fixed bottom-20 right-4 z-40`. Share is mounted after MobileNav, so it can sit directly on top of Compose and make a primary posting action inaccessible. | Give Compose and Share distinct positions and safe-area spacing, then test signed-in mobile layouts at common viewport sizes and as an installed PWA. |
| 🔴 P0 | Set browsing | `/set/:setId` renders `Explore`, and set cards link to `/set/<id>`, but `Explore` never reads the `setId` route parameter. A set URL can therefore open the generic Explore screen rather than the selected set. | Read `setId` with `useParams`, initialise/apply the set filter from it, keep URL/filter state in sync and add route tests for direct entry, back/forward and shared set links. |
| 🔴 P0 | Collector search | The main Search page invokes `search-profiles` with `{ query, limit }`, while the working profile-discovery flow uses `{ field, value, limit }`. Search swallows the failure and presents an empty result rather than an error. | Define one supported free-text profile-search contract, use it consistently, surface failures to the user and test local handles, names, DIDs and federated results. |
| 🔴 P0 | Feedback privacy | Opening the global Feedback form immediately captures `document.body` with `html2canvas` and uploads the screenshot before the user explicitly chooses to attach it or submits feedback. Because Feedback is mounted globally, this can capture Messages, Wallet, Settings and other private screens. Cancelling does not undo the upload. | Make screenshot attachment opt-in, show a preview before upload, redact/exclude sensitive regions, do not upload until explicit confirmation/submission, and provide deletion/cleanup for abandoned captures. |
| 🟠 P1 | Settings → Privacy | `collectionVisibility`, `tradeVisibility`, `locationPrecision`, `valueHidden` and `dataSaver` appear as real privacy/performance controls, but a full-source search finds those keys only in the settings UI/defaults. They do not appear to change website behaviour. | Either wire every control into the relevant rendering/data-loading paths and test it, or remove/label unavailable controls. Privacy controls must never be decorative. |
| 🟠 P1 | Presence privacy | The website automatically publishes signed-in presence heartbeats and publicly shows “Online Now”, while help copy says presence can be disabled in Settings. No such setting exists in the current Privacy settings UI. | Add a real presence visibility/heartbeat control, default it according to the intended privacy policy, stop/remove presence when disabled and update help/privacy copy. |
| 🟠 P1 | Guest action gating | Several public pages expose authenticated-only actions instead of prompting/signposting login. Home renders the full ComposeBox for guests, Card Detail always shows Add to Collection/Wishlist/Price Alert, Explore exposes bulk Add to Wishlist, and federated actor cards expose Follow. These actions can fail only after interaction. | Centralise auth-aware action gating. For guests, replace write controls with clear “Sign in to…” actions and preserve the intended return route after login. |
| 🟠 P1 | Pack Parties | A live party renders a prominent **Join Now** button with no `onClick` handler. | Implement the join flow and joined state, or hide/disable the button with an explicit “coming soon” state until the lifecycle exists. |
| 🟠 P1 | Post sharing | Every PostCard renders a Share icon button, but the button has no handler even though a working ShareDialog exists globally. | Connect per-post Share to the share dialog with the post’s canonical URL/content, or remove the non-functional control. |
| 🟠 P1 | Public challenge pages | Challenge Detail is public, but it calls an authenticated leaderboard/progress function and silently catches failure. With `data === null`, the main progress card can display its loading spinner indefinitely for signed-out visitors. | Detect guest state before invoking the protected request, provide a public-safe progress read or render a deliberate signed-out state instead of an endless loader. |
| 🟠 P1 | Public meetup pages | `/meetups/:meetupId` is routed as public, but MeetupDetail depends on an authenticated request. On failure it sets data to null and displays “not found”, conflating “login required” with a missing meetup. | Align route visibility with the data policy or provide a public-safe meetup summary. Render 401/403/not-found as distinct user states. |
| 🟠 P1 | Search UX | Search catches card/profile/federated request errors independently and converts them to empty arrays. A broken service therefore looks identical to “no results”. | Track per-source error states, show partial-results banners and retry controls, and never translate transport/API failures into a false zero-results state. |
| 🟠 P1 | SEO rendering | Route-specific title, canonical, Open Graph, Twitter, hreflang and JSON-LD are injected by `useSEO()` only after React mounts. The initial HTML contains generic site metadata, so crawlers/social unfurlers that do not execute JavaScript can receive the wrong page metadata. | Use server/edge rendering, static prerendering or host-level dynamic metadata for indexable/shareable routes. Keep the client hook only for in-app navigation updates. |
| 🟠 P1 | robots.txt / sitemap.xml | `/robots.txt` and `/sitemap.xml` are React SPA routes that render backend text inside `<pre>`. The React app itself cannot emit a true `text/plain` robots response or `application/xml` sitemap response, and no static robots/sitemap files exist in `public/`. | Serve both as real HTTP/static endpoints with correct content type, caching and status. Verify them from production with a non-browser HTTP client. |
| 🟠 P1 | Soft 404 / error page | The catch-all 404 is rendered inside the SPA, so correct HTTP 404 status is not guaranteed. The page is also hardcoded English/light-slate styling and exposes an admin-only internal message saying the AI may not have implemented the page and to ask it in chat. | Configure host-level 404 status/fallback behaviour, rebuild the page in the normal design/i18n system and remove all internal implementation/chat instructions from production UI. |
| 🟠 P1 | PWA offline mode | The service worker classifies every `.js`, `.css`, `.ts`, `.tsx`, etc. request as a “dev asset” and makes it network-only in production. It only precaches `/`, `/index.html` and `/manifest.json`. Offline navigation can therefore load cached HTML without the JS/CSS bundle needed to boot the app. | Limit dev bypass logic to development-specific paths/markers, precache the production build manifest/chunks or use a proven Workbox strategy, and test cold/offline launch after installation. |
| 🟠 P1 | PWA notifications | The service worker asks notifications to use `/icon-192.png` and `/icon-96.png`, but neither exists in `public/`. | Add real local notification/badge assets at the referenced paths, or use existing valid packaged assets, then test notifications on Chrome/Android and installed PWA. |
| 🟠 P1 | Status page accuracy | The status UI falls back to `service.current_status || 'operational'` when no live health result exists. Unprobed/stale services can therefore be presented as green rather than unknown. | Add explicit `unknown` and `stale` presentation, display last successful check, and never infer operational status from absence of live evidence. |
| 🟠 P1 | Consent continuity | The cookie banner defaults analytics/marketing off, but a signed-out choice lives only in localStorage. After later sign-in, Data & Privacy Rights treats a missing ConsentRecord as marketing/analytics/push enabled in its switch state. | Carry pre-login choices into the account after authentication, distinguish “not recorded” from enabled, and show the exact effective consent state consistently across banner and Settings. |
| 🟠 P1 | Private-page sharing | The global Share FAB is mounted on protected routes too, including Messages, Settings, Wallet, Admin and Moderation. It builds and shares the current pathname, so the UI actively invites users to share private/internal URLs such as `/messages/<conversationId>`. | Add a route-level share policy. Hide global sharing on private/internal pages and use resource-specific share controls only where the destination is intentionally public. |
| 🟠 P1 | Modal accessibility | The frontend contains dozens of hand-rolled full-screen overlays. A scan found 38 `fixed inset-0 z-50` overlays but only a small subset with explicit dialog semantics. Many custom modals therefore lack `role="dialog"`, `aria-modal`, labelled titles, focus trapping/restoration and consistent Escape behaviour. | Migrate custom overlays to the shared Radix Dialog/AlertDialog/Sheet primitives or implement the full accessible-dialog pattern centrally, then keyboard/screen-reader test each modal family. |
| 🟠 P1 | Settings accessibility | Shared `SettingRow` renders a visual label beside a `Switch`, but it does not pass an accessible name/id/`aria-labelledby` to the switch. This pattern is used across Privacy, Data Rights, Notifications, Accessibility and other settings. | Give each SettingRow switch a stable ID and programmatically associated label/description, or pass `aria-label`/`aria-describedby` through the component. |
| 🟠 P1 | Responsive legal/help navigation | On mobile, More contains docs/status/terms/privacy/chain/donate/GitHub; on large desktop these live in RightSidebar. At tablet widths (`md` to below `lg`), MobileNav is hidden and RightSidebar is also hidden, while LeftNav’s More dialog omits those links and normal pages have no global Footer. | Put legal/help/status links into the desktop More menu or render a global footer so every breakpoint exposes the same essential destinations. |
| 🟡 P2 | About page discoverability | `/about` exists and is SEO-configured, but no internal link to `/about` was found anywhere in the frontend. | Add About to an appropriate footer/More/legal navigation group and sitemap. |
| 🟡 P2 | Documentation deep links | Pages pass a `slug` to `DocumentationLink`, but the component ignores it for navigation and always opens the GitBook root. | Map slugs to their corresponding GitBook page URLs so contextual “Read official documentation” links land on the relevant guide. |
| 🟡 P2 | Native alerts/confirms | The website still contains many `alert()` and `window.confirm()` calls across compose, trades, pack parties, voting, binders, comments, settings and admin flows despite having toast/dialog primitives. | Replace native alerts/confirms with accessible, themed toast/AlertDialog patterns that preserve focus and work consistently in mobile WebViews/PWAs. |
| 🟡 P2 | Text selection | Global CSS disables `user-select` for the whole body and selectively re-enables it for a limited set of content classes. Ordinary profile/card/UI text can therefore be unnecessarily impossible to select/copy on desktop. | Default to normal text selection on the web. Disable selection only on specific drag/game/native-like controls where it materially improves interaction. |
| 🟡 P2 | Reduced-motion support | Route transitions and other animations run by default. The site has its own Reduce Motion setting, but no automatic `prefers-reduced-motion` handling was found, so a user’s OS accessibility preference is not honoured until they manually configure SwapPulse. | Initialise reduce-motion from the OS preference, use Framer Motion’s reduced-motion support and let an explicit in-app preference override it if desired. |
| 🟡 P2 | Global share vs resource share | The global ShareDialog shares `window.location.pathname` plus language rather than a resource-specific canonical URL. On dynamic pages this can be less useful than the page’s own entity URL/metadata, while PostCard’s local share button is disconnected. | Introduce a single share context/API that supplies canonical resource URL, title, description and optional media per page/entity. |
| 🟡 P2 | Public Search copy | Search tells all visitors it searches SwapPulse “and the federated network”, but federated-search is only invoked when `user?.id` exists. | Adjust guest copy or make public federated search available safely so the promise matches the actual result sources. |
| 🟡 P2 | Online collector links | `OnlineCollectors` falls back to `to="#"` when a Presence record has no handle, creating a clickable card that does not lead anywhere. | Link by DID when possible or render a non-link card when there is no resolvable profile route. |
| 🟡 P2 | Installed-app theming | `theme_color` in both `index.html` and `manifest.json` is permanently dark even though the site supports a light theme. Browser/PWA chrome can therefore remain dark while the app is light. | Update theme-color dynamically for light/dark mode and provide appropriate manifest/browser colour handling. |
| 🟡 P2 | Auth-page navigation | Standalone Login/Register/AuthLayout pages do not include a SwapPulse logo/home link or the normal site shell, making the route back to public browsing less obvious. | Add a clear SwapPulse/home affordance and essential legal links without cluttering the authentication flow. |
| 🟡 P2 | Frontend release verification | A fresh website build/lint run could not be performed because Base44’s command sandbox still mounts an empty `/workspace` with no `package.json`. | Run build, lint, typecheck policy and browser smoke tests in a correctly mounted canonical checkout and attach the results to the exact deployment commit. |
| 🟢 P3 | Language switcher listener | Each time LanguageSwitcher opens it adds an anonymous `keydown` listener for Escape, but cleanup removes only the mousedown listener. Repeated opens accumulate keydown handlers. | Store the keydown handler in a named function and remove it during effect cleanup. |
| 🟢 P3 | Search card thumbnails | Search results render trading-card art in a fixed `h-32 w-full object-cover` box, which can crop the card image rather than preserve its full portrait aspect ratio. | Use the shared CardImage/aspect-ratio presentation with `object-contain`/correct card ratio. |
| 🟢 P3 | PWA icon packaging | Manifest install icons are remote URLs and the same source is declared as both 192×192 and 512×512 with `purpose: "any maskable"`. This makes install identity dependent on external media availability and may not provide a maskable-safe asset. | Package local 192, 512 and maskable-safe icons in `public/` and reference them directly from the manifest. |

## Website strengths verified

The audit also found good frontend foundations worth preserving: route-level lazy loading is broadly applied; authenticated routes are separated from public browsing routes; the design system has consistent light/dark tokens; a skip-to-content link exists in the main layout; focus-visible styling is global; most major pages use the shared SEO hook; `<html lang>` is synchronised with the active locale after the app loads; external documentation/GitHub links generally use `noopener noreferrer`; mobile navigation includes safe-area padding; the app provides explicit accessibility controls; common UI uses consistent Radix/shadcn primitives in many newer areas; image/card components often provide alt text; the login flow has clear OTP timing and loading/error state; and the website already has a useful responsive shell that can be hardened rather than redesigned from scratch.

## Website release decision

The website should **not** be considered frontend-release ready until the P0 items are fixed and the P1 interaction/privacy/accessibility/PWA issues are either resolved or consciously removed from the exposed UI. The recommended order is: **mobile Compose/Share collision → set routing → collector search → feedback screenshot privacy → fake/dead privacy controls and presence preference → guest action gating and dead buttons → public-route loading/auth states → PWA/SEO correctness → accessibility/modal/settings fixes → responsive/legal/navigation polish**.

After remediation, rerun this website audit on the exact deployed frontend commit at phone, tablet and desktop widths, both signed out and signed in, plus installed-PWA/offline mode and keyboard/screen-reader smoke tests.
